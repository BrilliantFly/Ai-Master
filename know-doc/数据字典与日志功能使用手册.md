# 数据字典与日志功能使用手册

当前版本: 1.0.0

## 一、数据字典功能

### 1.1 概述

数据字典功能用于管理系统中的静态数据，如用户性别、岗位状态、菜单状态等。采用类型+数据的两层结构设计。

### 1.2 数据库设计

#### 字典类型表 (sys_dict_type)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| dict_name | varchar(100) | 字典名称 |
| dict_type | varchar(100) | 字典类型（唯一标识） |
| remark | varchar(500) | 备注 |
| status | tinyint | 状态 [0=停用, 1=正常] |
| create_time | bigint | 创建时间 |
| update_time | bigint | 更新时间 |
| delete_time | bigint | 删除时间 |

#### 字典数据表 (sys_dict_data)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| dict_type_id | bigint | 字典类型ID |
| dict_label | varchar(100) | 字典标签 |
| dict_value | varchar(100) | 字典值 |
| dict_code | varchar(100) | 字典编码（业务使用） |
| sort | int | 排序 |
| status | tinyint | 状态 [0=停用, 1=正常] |
| remark | varchar(500) | 备注 |
| create_time | bigint | 创建时间 |
| update_time | bigint | 更新时间 |
| delete_time | bigint | 删除时间 |

### 1.3 后端API

#### 字典类型接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /system/dict/type/list | 获取字典类型列表 |
| GET | /system/dict/type/{id} | 获取字典类型详情 |
| POST | /system/dict/type | 新增字典类型 |
| PUT | /system/dict/type | 修改字典类型 |
| DELETE | /system/dict/type/{id} | 删除字典类型 |

#### 字典数据接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /system/dict/list | 获取字典数据列表 |
| GET | /system/dict/{id} | 获取字典数据详情 |
| POST | /system/dict | 新增字典数据 |
| PUT | /system/dict | 修改字典数据 |
| DELETE | /system/dict/{id} | 删除字典数据 |

### 1.4 know-vue 前端使用

#### API调用

```typescript
import { 
  getDictTypeList, 
  getDictList, 
  addDictType, 
  updateDictType, 
  deleteDictType,
  addDict,
  updateDict,
  deleteDict 
} from '@/api/system/dict'

// 获取字典类型列表
const typeList = await getDictTypeList()

// 根据类型ID获取字典数据
const dictData = await getDictList(dictTypeId)
```

#### 页面使用

参考 `src/views/system/dict.vue`

### 1.5 know-uniapp 前端使用

#### 字典Store

```typescript
import { useDictStore } from '@/stores/dict'

const dictStore = useDictStore()

// 获取选项列表（用于picker等）
const sexOptions = dictStore.getDictOptions('sys_user_sex')
// 返回: [{ label: '男', value: '0', ... }, { label: '女', value: '1', ... }]

// 根据值获取标签
const label = dictStore.getDictLabel('sys_user_sex', '0')
// 返回: '男'
```

#### 工具函数

```typescript
import { getDictLabel, getDictOptions, formatDict } from '@/utils/dict'

// 获取用户性别选项
const sexOptions = getSexOptions()
// 返回: [{ label: '男', value: '0' }, { label: '女', value: '1' }]

// 获取性别标签
const sexLabel = getSexLabel('0')
// 返回: '男'

// 格式化显示（当找不到时返回默认值 '-'）
const display = formatDict('sys_user_sex', '0', '-')
// 返回: '男'

const display2 = formatDict('sys_user_sex', '99', '-')
// 返回: '-'
```

#### 初始化自动加载

字典数据在 App.vue 中自动加载：

```typescript
// 登录后自动加载所有字典数据
if (userStore.isLogin) {
  await initData()  // 包含用户信息和字典数据
}
```

手动刷新：

```typescript
import { useDictStore } from '@/stores/dict'

const dictStore = useDictStore()
await dictStore.refreshDictData()
```

## 二、操作日志功能

### 2.1 概述

操作日志功能用于记录用户在系统中的操作行为，包括操作模块、请求参数、返回结果等。

### 2.2 数据库设计

#### 操作日志表 (sys_oper_log)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| title | varchar(100) | 操作模块 |
| business_type | tinyint | 业务类型 [0:其他, 1:新增, 2:修改, 3:删除, 4:查询] |
| method | varchar(100) | 方法名 |
| request_method | varchar(10) | 请求方式 (GET/POST/PUT/DELETE) |
| operator_type | tinyint | 操作类型 [0:其他, 1:后台用户, 2:手机端用户] |
| oper_name | varchar(50) | 操作人 |
| oper_ip | varchar(50) | 操作IP |
| oper_location | varchar(255) | 操作位置 |
| oper_url | varchar(255) | 请求URL |
| oper_param | text | 请求参数 |
| json_result | text | 返回结果 |
| status | tinyint | 状态 [0:正常, 1:异常] |
| error_msg | text | 错误信息 |
| oper_time | bigint | 操作时间 |
| tenant_id | bigint | 租户ID |

#### 登录日志表 (sys_login_log)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| username | varchar(50) | 用户名 |
| ipaddr | varchar(50) | 登录IP |
| login_location | varchar(255) | 登录位置 |
| browser | varchar(50) | 浏览器类型 |
| os | varchar(50) | 操作系统 |
| status | tinyint | 状态 [0:失败, 1:成功] |
| msg | varchar(255) | 提示消息 |
| login_time | bigint | 登录时间 |
| tenant_id | bigint | 租户ID |

### 2.3 后端实现

#### @OperLog 注解

使用 `@OperLog` 注解自动记录操作日志：

```java
@OperLog(value = "用户管理", businessType = 1)
@PostMapping
public AjaxResult add(@RequestBody SysUser user) {
    return AjaxResult.success(userService.add(user));
}
```

注解属性：

| 属性 | 类型 | 说明 |
|------|------|------|
| value | String | 操作模块 |
| businessType | int | 业务类型，默认0 |
| operDesc | String | 操作描述，默认空 |

#### 后端API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /system/log/oper/page | 分页查询操作日志 |
| GET | /system/log/oper/list | 获取操作日志列表 |
| DELETE | /system/log/oper/{id} | 删除操作日志 |
| DELETE | /system/log/oper/clear | 清空操作日志 |
| GET | /system/log/login/page | 分页查询登录日志 |
| GET | /system/log/login/list | 获取登录日志列表 |
| DELETE | /system/log/login/{id} | 删除登录日志 |
| DELETE | /system/log/login/clear | 清空登录日志 |

#### AuthController 登录日志

登录时自动记录登录日志：

```java
// 登录成功
saveLoginLog(username, ipaddr, 1, "登录成功", userAgent);

// 登录失败
saveLoginLog(username, ipaddr, 0, "密码错误", userAgent);

// 登出
saveLoginLog(username, ipaddr, 1, "退出成功", userAgent);
```

### 2.4 know-vue 前端使用

参考 `src/views/system/dict.vue` 类似的列表页面，使用 `/system/log/oper/*` 和 `/system/log/login/*` 接口。

### 2.5 know-uniapp 前端

uniapp端目前不直接展示日志管理页面，但登录日志会在后端自动记录。

## 三、权限指令使用

### 3.1 know-vue 权限指令

#### v-permission 指令

```vue
<template>
  <!-- 单个权限 -->
  <button v-permission="'system:user:add'">新增</button>
  
  <!-- 多个权限（满足其一即可显示） -->
  <button v-permission="['system:user:add', 'system:user:edit'">操作</button>
</template>
```

#### 编程式检查

```typescript
import { hasPermission } from '@/utils/permission'

// 检查单个权限
const canEdit = hasPermission('system:user:edit')

// 检查多个权限
const canOperate = hasPermission(['system:user:add', 'system:user:edit'])

if (canEdit) {
  // 执行操作
}
```

### 3.2 后端权限拦截器

JwtPermissionFilter 自动从数据库加载用户权限并校验：

```java
// 根据用户ID获取权限编码列表
List<String> permissionCodes = sysPermissionService.listCodesByUserId(userId);

// 权限校验
if (!hasPermission(permissionCodes, requiredPermission)) {
    return 403;
}
```

## 五、常见问题

### 5.1 字典数据不显示

1. 检查后端 `sys_dict_type` 和 `sys_dict_data` 表是否有数据
2. 检查know-uniapp是否已登录（未登录不加载字典）
3. 调用 `dictStore.refreshDictData()` 手动刷新

### 5.2 权限校验失败

1. 检查用户是否绑定了角色
2. 检查角色是否分配了权限
3. 检查用户ID是否为1（超级管理员自动放行）

### 5.3 日志未记录

1. 检查方法是否有 `@OperLog` 注解
2. 检查 AOP 切面是否生效
3. 检查数据库连接是否正常
